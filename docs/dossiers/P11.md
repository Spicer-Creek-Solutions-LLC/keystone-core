# Dossier — P11, Repository skeleton and CI

The task that gives this repository the ability to check anything.

**That is not a figure of speech.** `git ls-files` returns no script; `make check`
runs three documentation gates and the capability catalog. Every acceptance
verification across eleven tasks has been performed once, by hand, and retained
at best as an inert code block inside an evidence file. `G21` recorded it: *"the
protection against P00's claim coming back is the same protection that failed for
it — someone remembering to look."*

**And `ADR-0010` § 14 states that `ARCH-TEST-003` is not satisfied** while every
row of the invariant register names a file that does not exist. P11 is where the
first of them either does or does not.

So P11's title understates it. It is the last task in Stage P, its gate is
**P00–P10** — the only task in the epic that depends on everything before it —
and it converts the entire planning stage from documents into something that can
fail.

This dossier is a boundary, not an approval. Landing it authorizes nothing: P11
still needs its own presented plan and explicit approval. P11 is a planning and
tooling task and may use one pull request; it does not split into `-A` and `-I`,
because no command-execution behaviour lands in it. Program rule 6's separation
is met by the independent reviewer named in § 8.

## 11. Decisions requiring confirmation at P11 approval

**All four were confirmed by the maintainer before this dossier was written**, and
the rulings are recorded here rather than left in the approval conversation.

### `D-P11-1` — the whitespace gate, and what the existing one does not see

**The diagnosis is not that a whitespace gate is missing.** `markdownlint`'s
MD009 is enabled and does flag trailing spaces. It did not flag #323's because
**markdownlint skips fenced code blocks**, and that trailing space was inside a
` ```text ` demonstration record.

**That is where every generated artifact in this repository lives.** Each
acceptance-evidence file carries a demonstration record and an embedded checker
inside fences — content written by a generator and reviewed by nobody line by
line. The gate exists and does not reach the content most likely to need it.

**Ruling: a whitespace lint over every tracked text file, enumerated from
`git ls-files`.** Not `git diff --check`, which is range-dependent — bare, it
compares the worktree to the index, which after a clean CI checkout is empty, so
the gate would pass unconditionally. **A gate built on a diff range is a gate that
can be vacuous**, and that is `DL-1` shipped as a gate.

Enumerating from git also repeats a lesson the `Makefile` already learned aloud:
`docs-links` takes its file list from git because a glob *"silently disagreed
about what 'every tracked file' meant."* A diff range has the same shape of
hidden assumption.

**Pre-existing hits are fixed, not excluded.** An exclusion list is how the
docs-lint glob went wrong, and the `Makefile` says so.

MD009 cannot be configured to cover fenced content — `br_spaces`,
`list_item_empty_lines` and `strict` do not extend it — so this is an addition
rather than a configuration change.

### `D-P11-2` — the standing sweeps get a home; the acceptance cases do not

Roughly eight thousand lines of checker exist in scratchpads and **none has ever
been committed**. They are two different things:

- **An acceptance case is one-time.** A case asserting that some section states
  retention as an inequality proves an ADR was correct when accepted. Once stable it passes forever, and a
  later legitimate amendment turns it into a false failure someone disables.
- **A sweep is standing.** A rule asserting that no tracked file gates a risk on
  P10 says the conclusion **has not been contradicted since**, which is a claim
  about the future.

**The evidence separates them.** Every cross-task catch in this stage came from a
sweep or a cross-document consistency check — `P10`'s dossier checker failing
after `G22` changed `P02.md`; `AC-11` finding `THREAT-MODEL.md` and `ADR-0008`
still forward-referencing; `G22`'s sweep failing after P10 reworded a risk cell.
**No per-ADR structural case has ever caught a later regression.** The
demonstration harnesses are one-time by construction.

**Ruling: retain the standing sweeps only, in Go, as `tools/doclint`.** Go
because `tools/capcheck` sets the precedent — its own module, and CI already has
a Go toolchain — and because P11 is the task that sets tooling conventions and
the moment to set one language is now.

**Each rule states a lifetime.** A sweep guards a correction, and every task adds
one, so without lifetimes the rule set grows monotonically until nobody reads its
failures. A rule retires when the corrected text has been stable across a stated
number of tasks, **and the retirement is recorded rather than silent**.

**The cost, stated:** translating a working Python check into Go risks
introducing a defect in a check that currently passes. Each rule's translation is
demonstrated failing on the same planted defect the original caught.

### `D-P11-3` — a traceability lint whose liveness derives from the epic

`REQUIREMENTS-TRACEABILITY.md`'s own rule says **"CI must fail when an implemented
invariant lacks its registered evidence."** At P11 almost nothing is implemented,
so that rule's precondition is nearly empty and it would pass as coverage for the
whole of Stage C. `DL-1`.

Much is checkable now: every invariant has a row and every row an invariant;
every **design owner** names a document that exists — the rule that would have
caught *"Test architecture ADR"* long before `ADR-0010` did; every **gate** is one
`TESTING.md` schedules; identifiers are unique.

**Ruling: the register gains a `Lands at` column naming the task that owes each
row's evidence, and the lint derives liveness from the epic.** It asserts the
named task exists in the execution plan, and **if the epic shows that task
complete, the evidence must exist.**

**That converts a vacuous rule into one that becomes live automatically, task by
task, with no dates to maintain.** It also stops the 24 rows being permanent
targets: each names who owes it. The epic's `- [x]` is already machine-readable.

This is the shape the execution plan already uses for behaviour workstreams — a
*"machine-checked `pending-requirements` manifest with an owner and expiry"* —
applied to the register, which had no equivalent.

**Expect the lint to fail the first time it runs.** Some `Lands at` values will
be wrong or unassignable. That is the check working.

### `D-P11-4` — scaffolding, not stubs

The charter fixes three binaries and seven journey verbs. P11's brief says
*"minimal command packages"* and *"no command-execution behavior lands here."*

**Ruling: the three binaries, shared configuration conventions, exit-code
constants, version logic and the Docker harness shell. No verbs.**

**What decides it is that this is the only option that pays a register row at
P11.** `ADR-0010` § 2 requires the topology's isolation to be **proved by a
probe**, and three binaries that merely start are enough to stand the topology up
and run it. That file is exactly what `ARCH-COMM-002`'s row registers, so the row
moves from a target to a path that exists and runs — with no product behaviour
anywhere.

**That is a smaller claim than satisfying the invariant, and review of #330 was
right to force the distinction.** `ARCH-COMM-002` requires the parts to *work*
without direct reachability; P11 proves only that they cannot dial each other.
The register's own framing is what P11 pays against — *"the test paths are targets
for the clean baseline; they become mandatory as the corresponding implementation
lands"* — and one path landing is still the difference between a map that is
wholly aspiration and one that is not.

Seven verb stubs pay no row at all.

**A verb stub also has no honest exit code.** The charter's `1` is *"local or
usage error: bad arguments, unreadable configuration"*, which a working binary
refusing a valid command is not; there is no *not implemented* code, and adding
one is a charter amendment and out of bounds.

**The cost, stated:** nothing in P11 asserts the seven journeys will exist, so
the charter's surface stays unbound until C04. `D-P11-3`'s `Lands at` records who
owes each one, which is the weaker guarantee and the honest one.
