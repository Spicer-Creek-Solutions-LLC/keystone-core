# R10 — Independent transition audit

**Verdict: the gate is BLOCKED.** One Critical and ten distinct High findings
are unresolved. Under the acceptance criterion in
[`REBOOT-EXECUTION-PLAN.md`](../../project/REBOOT-EXECUTION-PLAN.md) § R10,
implementation cannot begin until each is resolved or carries a maintainer
risk acceptance naming an owner and an expiry.

**Preservation succeeded. The reset is incomplete, and the record of both is
unreliable.** That split is the headline. Every artefact the transition was
meant to protect is intact and verified — archive refs resolve on both forges,
the tag signature is good, the bundle is self-consistent and the Generation 1
tree is fully recoverable. What failed is everything downstream of preservation:
public surfaces still present Generation 1 as current, several retained
documents assert controls that do not exist, and the transition manifest
contains claims that are false.

## Scope and method

Four agents audited in parallel. None had performed R05-R09 and none inherited
the performing agent's context. Each was instructed that `docs/transition/` is
the object under audit rather than evidence for it, and that a `403` from a
non-admin token is a verification limit and never a pass.

## Independence limit

This report was assembled by the agent that performed R05-R09. It is auditing
its own work. Two structural mitigations apply: every raw finding appears in the
reconciliation table with a disposition, so none can be dropped silently; and
the raw reports are committed alongside, so any disposition can be checked
against its source.

Neither mitigation covers the failure mode this transition has already
demonstrated three times — a check that cannot fail, mistaken for evidence. The
assembling agent wrote all three instances. A reader who wants that class of
defect caught should read the raw reports directly.

One severity was changed (`D-12`, MEDIUM to INFO) and one figure corrected
(`A-05`). Both are argued in the table. No finding was dismissed.

## What must be decided

### Critical

**`D-01` — `docs.keystone-core.io` serves the Generation 1 documentation site.**
The domain is the `website` field on both forges and the first link in several
documents. It is generated by Hugo 0.163.3 — the toolchain R08 deleted — and
describes the control plane in the present tense with no mention of the reboot.
R09 rewrote `deploy/docs/site/index.html` in the repository but deploying it is
a manual step that has not happened. Until it does, the project's own
documentation domain contradicts the reboot at every point.

This also corrects a statement the assembling agent made repeatedly: the live
page is not the old placeholder, it is the full site.

### High, grouped by what caused them

**The record is wrong about the GitHub mirror (`B-11`, `A-07`, `D-08`).** The
mirror is alive, synced to `47ae589b8`, and carries both archive refs. The claim
that it is dead at `0a476caaa` appears in `manifest.json`, the execution plan,
pull request #279 and R09's status line. R05's "both forges" acceptance was
therefore met, and the maintainer was told twice that a repair was needed.

**The archive record misstates what the bundle uniquely holds (`A-05`, `A-06`).**
The manifest says the divergent commits are content-duplicates; they are not.
It says the bundle holds the four commits `git filter-repo` removed; it does
not, and those four survived only as unreachable objects on one machine. Both
claims were written by the assembling agent, the second as a correction to an
earlier overstatement. The correction's own evidence — 120 sampled
original/replacement pairs with identical trees — was gathered with
`refs/replace` substitution active, so both sides of every pair resolved to the
same object and the comparison could not have failed.

**Retained documents assert controls that do not exist (`C-03`/`D-09`,
`C-02`/`D-07`/`D-03`).** `SECURITY-GOVERNANCE.md` states that four scans gate
every pull request, that the Go toolchain is pinned in `go.mod`, and that a
release dry-run runs per pull request. None is true and there is no root
`go.mod`. The pull-request template requires five `make` targets that no longer
exist; the bug-report form asks a reporter for `kscorectl --version` and
`journalctl -u kscore-server`. R08 chose to retain these files. Retaining a file
is not the same as reconciling its contents, and they were not reconciled.

**A gate has a blind spot that hid one of the above (`C-01`).** lychee's
`**/*.md` does not match dot-directories, so `.forgejo/` has never been
link-checked. R09 widened the markdown-lint glob to `**/*.md` and left lychee's
identical-looking glob untouched; the two tools treat the same pattern
differently.

**Public claims that are simply false (`D-02`, `D-04`, `D-05`, `D-06`).** Both
forge descriptions still advertise Generation 1 capability. `ISSUE-TRACKING.md`
says the announcement is pinned; it is not, and R09's own log records the 403.
`README.md` says the tracker is empty by design; it holds fourteen open issues
that R09 created. `SECURITY.md` routes a vulnerability reporter to
`OWNERSHIP.md`, which lists no address and tells them to open a public issue —
the one thing `SECURITY.md` forbids.

## What the audit confirmed

Stated plainly, because it is the larger half of the result.

Both archive refs resolve to `93eb147f7` on Codeberg *and* GitHub. The tag is a
genuine annotated tag with a good signature from the expected key. The bundle's
SHA-256 matches, `git bundle verify` passes, and its archive history is
identical to the remote's — 768 commits, zero difference either way. The
Generation 1 tree is fully recoverable: 1,962 files, 1,545 of them Go. The
`v0.1.0`, `v0.5.0` and `archive/v0-final` tag objects match the R02 record
exactly.

All 106 retirements are real and uniform — auditor B pulled every timeline
rather than sampling and found one comment, two label additions and one closure
each, with zero title changes. Every issue number from 1 to 282 resolves:
nothing was deleted. All five Generation 1 milestones are closed and intact.
Both releases are published with 20 assets each at their original upload
timestamps, carrying the archived notice exactly once above intact original
notes. `main` requires exactly one status context and it is the mergeable one,
so the trigger-suffix trap was avoided.

Auditor C planted defects and proved that `docs-lint`, `docs-links` on normal
paths, `capability-catalog-check`, `stray-binary-check` and the DCO check all
genuinely fail when they should, and that no gate is silently skipped when its
tool is missing.

## What could not be verified

Recorded as limits, not as passes.

- **Tag protection.** `/tag_protections` returns 403 to a non-admin token and
  tag reads carry no protection field. Unverifiable for the second time; R05
  recorded the same limit.
- **Branch-protection rules.** `protected: true` is observable; the specific
  force-push, deletion and allowlist flags are not.
- **Bundle custody copies** on the maintainer's NAS and workstation.
- **Whether issue bodies and comments were edited.** Forgejo emits no timeline
  event for either, so "content intact" rests on zero title changes and the
  absence of any deletion.
- **Package-registry landing pages.** The token lacks `read:package`.
- **The `docker` runner image** and whether the current workflow has ever run
  green on `main` as opposed to on pull requests.
