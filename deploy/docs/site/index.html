Keystone Core

GitOps deploys it. We keep it running.

There is nothing to install. In September 2026 the project accepted a reboot. The Generation 1 implementation was archived rather than continued, and the repository now holds planning, governance and transition evidence. The replacement has not been written.

Why

Not because it failed to work. Because its breadth outran the evidence that any single operator journey worked end to end. Late fixes had found enrollment credentials that were not retained, and state and blueprint applies that did not reliably reach remote agents — cases where package-level test coverage sat alongside missing production wiring. Adding features would have preserved that risk rather than resolved it.

Nothing was deleted

The final Generation 1 state is preserved on the protected branch archive/2026-09-pre-v0.6-reboot, at the signed tag archive-2026-09-pre-v0.6-reboot, and in an offline bundle held by the maintainer. The v0.1.0 and v0.5.0 releases remain published with their artifacts intact.

They are unsupported. They receive no updates, including security updates, and there is no supported release of Keystone Core at this time.

What Generation 2 is

One promise, deliberately narrow: an operator can securely enroll a Linux agent, target it, execute a bounded command over NATS, observe its durable lifecycle, cancel it, and retrieve an auditable result.

Nothing else ships until that is demonstrably true — proven by black-box tests driving production binaries across the real transport. State management, blueprints, runbooks, plugins, secrets, GitOps, webhooks, policy and clustering are Future candidates rather than commitments.

Where to read

Documentation lives as Markdown in the source repository. There is no rendered site: the Hugo toolchain was part of Generation 1 and was removed with it. A documentation site returns when there is software to document.
