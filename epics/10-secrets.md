# Epic 10: Secrets Management

**Phase**: F • **Estimate**: 1.5 weeks • **Depends on**: 02, 03, 09 • **Blocks**: 14, 15

## Goal

Unified broker for secret retrieval, lease management, and encryption-as-a-service. Encrypted-file backend (zero-deps) and HashiCorp Vault backend (most common in trial environments). Lease lifecycle, transit ops, encrypted in-memory cache, audit emission.

## Scope (in)

- `internal/secrets/` broker:
  - `SecretBroker` with **path-prefix routing** (longest-match-first).
  - `SecretBackend` interface: `GetSecret`, `WriteSecret`, `ListSecrets`, `DeleteSecret`, `IssueDynamicSecret`, `RenewLease`, `RevokeLease`.
  - Audit hook: every operation emits `secret.access` event with agent ID, SPIFFE ID, action, path, timestamp, duration; sensitive data masked via `LogMasker`.
- v1.0 backends:
  - **Encrypted-file** (`internal/secrets/file/`): AES-GCM, JSON serialization, master key from env or KMS. Zero external deps.
  - **HashiCorp Vault** (`internal/secrets/vault/`): KV v1/v2, dynamic secrets (DB, IAM, PKI, SSH), transit, namespace support, all auth methods (token, AppRole, K8s, AWS IAM, LDAP).
- `LeaseManager`:
  - Persistent SQLite store (`pkg/secrets`-shaped types `LeaseInfo`, `Lease`).
  - In-memory tracking; background scheduler with strategy `eager` (50% TTL), `lazy` (90% TTL), `on_demand`.
  - Renewal callbacks for lifecycle events.
  - Bulk ops: list, revoke, expire-cleanup.
- `TransitBackend` (Vault transit engine): encrypt/decrypt/sign/verify/HMAC; batch ops; key versioning; convergent option; data-key generation for envelope encryption; rewrap.
- `SecretCache`: in-memory L1, AES-GCM at-rest, TTL eviction (default 5m), prefix-deletion on revoke; bounded-LRU; stats (hits/misses/evictions/expired/memory).
- `pkg/secrets` client lib + types (`Secret`, `Lease`, errors) for in-process consumers.
- `pkg/api/secrets/` REST handlers + gRPC `SecretsService` impl: `GetSecret`, `ListSecrets`, `WriteSecret`, `DeleteSecret`, `GetLease`, `ListLeases`, `RenewLease`, `RevokeLease`, `Encrypt`, `Decrypt`, `Sign`, `Verify`.
- `cmd/kscore-secrets` CLI: `get`, `list`, `backends`, `audit`, `dynamic`, `leases`, `cache`, `encrypt`, `decrypt`, `template`.
- Secret masking in API responses (`***`) — cleartext only on creation/get-for-use; never in list responses.

## Scope (out / non-goals)

- Rotation orchestration with strategies (blue-green/rolling/canary/immediate; health checks; auto-rollback) — v1.4.
- Cron-based rotation scheduling + Slack/PagerDuty notifications — v1.4.
- Compliance reports + anomaly detection — v1.4.
- AWS Secrets Manager / Azure Key Vault / GCP Secret Manager backends — v2.0.
- Cloud KMS for master keys — v2.0.
- Hardware HSM (PKCS#11) — v2.x.
- L2 KMS-backed cache — v2.0.

2. **Path-prefix routing engine** — longest-match-first; tests for ambiguous configs.
   _(landed: `internal/secrets.Router` + `Route{Prefix, Backend}`. `NewRouter` validates each row (non-empty prefix, no leading `/` because [Secret.Path] is unrooted per task 1, no whitespace / non-printable bytes per the defensive-hardening pattern from Epic 05 envelope validation, non-empty backend), then detects duplicate prefixes across the whole table and surfaces every offender in one error message so operators fix the config in one pass. All rejections wrap `ErrInvalidBackend` for `errors.Is`. Trailing-slash semantics: `prefix: secret` (no slash) matches both `secret/foo` AND `secretstore/foo`; the test pins that as the documented Vault-style behavior so a future auto-segment refactor is intentional. Empty-prefix policy: rejected at construction because §4.11's `default_backend` config knob already covers the "no prefix matched" fallback (broker task 3 wires it). 93.4% coverage on the package; `-race` clean; project-wide `make lint` + `make test` green.)_

8. **`SecretCache`** with AES-GCM + TTL + LRU + prefix-delete + stats.
   _(landed: `internal/secrets.SecretCache` implements the task-3 `Cache` interface with AES-256-GCM at-rest encryption + bounded LRU + TTL expiry + background sweep + operator `Clear()`. **At-rest key**: `crypto/rand`-generated per-instance 32-byte AES-256 key (never persisted; cache wipes on restart by design). Defense-in-depth against memory inspection (debugger / core dump / container snapshot) — NOT a confidentiality boundary against in-process callers. Every `Put` JSON-marshals the `Secret`, generates a fresh 12-byte nonce, encrypts under the cache's AEAD; every `Get` decrypts + unmarshals into a fresh `*Secret`. **Nonce uniqueness** asserted in tests (two Puts of identical plaintext produce different ciphertexts — defense against accidental ECB-like leakage). **Defensive copy by construction**: caller mutations of the returned `*Secret` do NOT affect the cached entry (JSON round-trip is the boundary). **LRU**: `container/list` doubly-linked list + `map[string]*list.Element` for O(1) lookup; on `Get` hit the entry moves to front; on `Put` past `MaxEntries` the tail evicts. **TTL eviction**: each entry stamps `expiresAt = now + DefaultTTL`; `Get` returns miss + reaps the entry when `now.After(expiresAt)` is true. **Sweep goroutine**: background reaper ticks every `SweepInterval` (default 30s) walking the LRU and dropping expired entries — reclaims memory between accesses (without the sweep, expired-but-never-re-accessed entries stay resident until LRU eviction). Defaults: `DefaultCacheTTL = 5m`, `DefaultCacheMaxEntries = 10000`, `DefaultCacheSweepInterval = 30s` — exactly the §4.11 config-example numbers. Negative config values rejected; zero falls through to defaults. **Lifecycle**: `Start(ctx)` spawns the sweep; `Stop(ctx)` cancels with deadline; double-Start / Start-after-Stop rejected; Stop idempotent. **Cache is usable without Start** — the sweep is purely a background optimization; manual `Get`/`Put`/`InvalidatePath`/`InvalidatePrefix` work fine. **Operator surface beyond `Cache` interface**: `Clear()` drops every entry + resets counters (used by the future `kscore-secrets cache clear` CLI after a master-key rotation). Compile-time interface assertion `var _ Cache = (*SecretCache)(nil)`. **Internal failure modes**: AEAD decryption failure on `Get` (corrupted entry — should never happen short of bit rot) logs ERROR, drops the entry, returns miss so the caller falls back to the backend; marshal/encrypt failure on `Put` logs ERROR and skips the cache (the live backend call already succeeded — the broker still returns the secret to the caller). Test surface: 19 test functions covering construction validation (3 cases — negative TTL/MaxEntries/SweepInterval), defaults populate, round-trip with full `Secret` shape (Path/Data/Metadata/Version/LeaseID/LeaseDuration/Renewable/CreatedAt), nonce + ciphertext uniqueness across re-puts of identical plaintext, mutation isolation (caller can't mutate cached state), miss-counter increments on cold lookup, TTL expiry past the deadline + at-the-boundary alive, LRU bump on Get (recently-touched entry survives eviction), LRU cap enforcement (5 puts past 3-cap → 2 evictions), Put-same-path replaces (not duplicates), `InvalidatePath` drops exact match only / safe on missing path, `InvalidatePrefix` drops every entry under prefix / empty prefix is a no-op (NOT a wipe), `Clear` empties + resets counters + zeros MemoryBytes, Stats accuracy across hits/misses/entries/MemoryBytes, **background sweep** end-to-end (clock-advance past TTL → wait for sweep tick → entry reaped + Expired counter populated, asserted within 2s deadline), lifecycle (Start/Stop/double-Start/Start-after-Stop), usable-without-Start, N=50 concurrent Put/Get/InvalidatePath under `-race`, **broker integration** test boots a real `Broker` against `SecretCache` and asserts the §4.11 acceptance criterion `cache hit-rate > 80% on second access of same secret` (10 sequential Gets → 1 backend dispatch → hit rate 9/10 = 90%). 91.8% coverage on `internal/secrets`; project `make lint` + `make test` + `make docs-lint` + `-race` clean.)_

## Acceptance criteria

- [ ] Encrypted-file backend: write secret → read secret → delete secret round-trips with AES-GCM authenticated encryption.
- [ ] Vault backend (with `vault dev` server) — KV v2 read/write, dynamic DB credential issuance, lease renewal, lease revoke.
- [ ] Path-prefix routing: `kv/app/db` routes to file backend; `secret/data/foo` routes to Vault per config.
- [ ] Lease manager: dynamic secret issued → tracked → renewed at threshold → revoked on demand → removed from tracking.
- [ ] Transit ops: encrypt → decrypt round-trips; signed message verifies; batch encrypt 100 plaintexts in <1s with Vault.
- [ ] Cache hit-rate >80% on second access of same secret; cache invalidates on prefix-delete.
- [ ] All operations emit `secret.access` event in audit log with masked values.
- [ ] CLI: `kscore-secrets get path` returns cleartext (with audit log entry); `list` shows path + metadata only.
- [ ] Coverage >75% on `internal/secrets`; >80% on `pkg/secrets`.

## Risks

- **Cache invalidation on backend update** — explicit (refresh param or operator clear). Document.
- **Master-key rotation** breaks cache — mitigate with dual-key window.
- **Transit round-trips** add 50–200ms — batch ops materially help.
- **Lease renewal storms** — add jitter (default scheduler has it).
- **Audit log disk-full** — circuit-break + alert is mandatory.
- **Vault test dependency** — gate Vault tests behind `KSCORE_TEST_VAULT_ADDR`; CI runs `vault dev` in docker-compose.
