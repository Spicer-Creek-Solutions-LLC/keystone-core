# Epic 10: Secrets Management

**Phase**: F • **Estimate**: 1.5 weeks • **Depends on**: 02, 03, 09 • **Blocks**: 14, 15

## Goal

Unified broker for secret retrieval, lease management, and encryption-as-a-service. Encrypted-file backend (zero-deps) and HashiCorp Vault backend (most common in trial environments). Lease lifecycle, transit ops, encrypted in-memory cache, audit emission.

## Scope (in)

- `internal/secrets/` broker:
  - `SecretBroker` with **path-prefix routing** (longest-match-first).
  - `SecretBackend` interface: `GetSecret`, `WriteSecret`, `ListSecrets`, `DeleteSecret`, `IssueDynamicSecret`, `RenewLease`, `RevokeLease`.
  - Audit hook: every operation emits `secret.access` event with agent ID, SPIFFE ID, action, path, timestamp, duration; sensitive data masked via `LogMasker`.
- v1.0 backends:
  - **Encrypted-file** (`internal/secrets/file/`): AES-GCM, JSON serialization, master key from env or KMS. Zero external deps.
  - **HashiCorp Vault** (`internal/secrets/vault/`): KV v1/v2, dynamic secrets (DB, IAM, PKI, SSH), transit, namespace support, all auth methods (token, AppRole, K8s, AWS IAM, LDAP).
- `LeaseManager`:
  - Persistent SQLite store (`pkg/secrets`-shaped types `LeaseInfo`, `Lease`).
  - In-memory tracking; background scheduler with strategy `eager` (50% TTL), `lazy` (90% TTL), `on_demand`.
  - Renewal callbacks for lifecycle events.
  - Bulk ops: list, revoke, expire-cleanup.
- `TransitBackend` (Vault transit engine): encrypt/decrypt/sign/verify/HMAC; batch ops; key versioning; convergent option; data-key generation for envelope encryption; rewrap.
- `SecretCache`: in-memory L1, AES-GCM at-rest, TTL eviction (default 5m), prefix-deletion on revoke; bounded-LRU; stats (hits/misses/evictions/expired/memory).
- `pkg/secrets` client lib + types (`Secret`, `Lease`, errors) for in-process consumers.
- `pkg/api/secrets/` REST handlers + gRPC `SecretsService` impl: `GetSecret`, `ListSecrets`, `WriteSecret`, `DeleteSecret`, `GetLease`, `ListLeases`, `RenewLease`, `RevokeLease`, `Encrypt`, `Decrypt`, `Sign`, `Verify`.
- `cmd/kscore-secrets` CLI: `get`, `list`, `backends`, `audit`, `dynamic`, `leases`, `cache`, `encrypt`, `decrypt`, `template`.
- Secret masking in API responses (`***`) — cleartext only on creation/get-for-use; never in list responses.

## Scope (out / non-goals)

- Rotation orchestration with strategies (blue-green/rolling/canary/immediate; health checks; auto-rollback) — v1.4.
- Cron-based rotation scheduling + Slack/PagerDuty notifications — v1.4.
- Compliance reports + anomaly detection — v1.4.
- AWS Secrets Manager / Azure Key Vault / GCP Secret Manager backends — v2.0.
- Cloud KMS for master keys — v2.0.
- Hardware HSM (PKCS#11) — v2.x.
- L2 KMS-backed cache — v2.0.

2. **Path-prefix routing engine** — longest-match-first; tests for ambiguous configs.
   _(landed: `internal/secrets.Router` + `Route{Prefix, Backend}`. `NewRouter` validates each row (non-empty prefix, no leading `/` because [Secret.Path] is unrooted per task 1, no whitespace / non-printable bytes per the defensive-hardening pattern from Epic 05 envelope validation, non-empty backend), then detects duplicate prefixes across the whole table and surfaces every offender in one error message so operators fix the config in one pass. All rejections wrap `ErrInvalidBackend` for `errors.Is`. On success the table is sorted longest-prefix-first with lexicographic ascending tie-break so two same-length prefixes have a deterministic order; `sort.SliceStable` keeps the sort observable across runs. `Lookup(path) (Route, bool)` is a linear `strings.HasPrefix` scan over the pre-sorted slice — no normalisation (paths are opaque keys at this layer); returns the full `Route` so the broker can audit the matched prefix verbatim. `Routes()` returns a defensive copy and `Len()` reports the table size. Trailing-slash semantics: `prefix: secret` (no slash) matches both `secret/foo` AND `secretstore/foo`; the test pins that as the documented Vault-style behavior so a future auto-segment refactor is intentional. Empty-prefix policy: rejected at construction because §4.11's `default_backend` config knob already covers the "no prefix matched" fallback (broker task 3 wires it). 93.4% coverage on the package; `-race` clean; project-wide `make lint` + `make test` green.)_
3. **`SecretBroker`** with cache integration + audit emission.
   _(landed: `internal/secrets.Broker` is the single entry point higher layers (REST handlers, gRPC service, CLI) talk to per §4.11. Joins the task-2 [Router] (path-prefix routing), a `map[name]SecretBackend` registry, a [Cache] consulted on reads and invalidated on writes/deletes/revokes, an [Auditor] that records every operation, and a [LeaseDirectory] that maps `LeaseID → (backend, path)` so lease ops route without caller knowing which backend issued them. Cache + Auditor + LeaseDirectory ship as **interfaces + no-op / in-memory defaults** here; task 8 (AES-GCM cache), task 11 (audit-store integration), and task 6 (persistent LeaseManager) swap in real implementations without touching the broker. `BrokerConfig` validates: at least one backend, unique Names(), default_backend (if set) names a registered backend, every router route's backend resolves at boot (catches config drift fast). Nil cache/auditor/leases default to `NoopCache` / `NoopAuditor` / `InMemoryLeaseDirectory`. `Start(ctx)` fans out to every backend's `Start` with rollback on failure (already-started backends best-effort stopped); double-Start rejected; Start-after-Stop rejected. `Stop(ctx)` is idempotent; per-backend errors logged but continue. `Health(ctx)` aggregates (first unhealthy backend wins, with its name in the error). Seven dispatch methods (`GetSecret` / `WriteSecret` / `ListSecrets` / `DeleteSecret` / `IssueDynamicSecret` / `RenewLease` / `RevokeLease`) share a shape: extract principal from ctx → router lookup (DefaultBackend fallback) → `HasCapability` check (CapKV / CapList / CapDynamic / CapLeaseRenew / CapLeaseRevoke as appropriate) → dispatch (with cache layer for GetSecret only — Refresh bypasses) → emit one `SecretAccessEvent` regardless of outcome (failure-to-log = bug per §4.11). `GetSecret` populates cache on success; `WriteSecret` / `DeleteSecret` invalidate the path; `IssueDynamicSecret` records `LeaseID → (backend, path)`; `RenewLease` against a backend-reported `ErrLeaseExpired` forgets the lease so a follow-up renew gets the canonical `ErrLeaseNotFound`; `RevokeLease` on success forgets the lease + invalidates the lease's secret-path cache entry. `Principal` (`AgentID` / `SPIFFEID` / `User`) is populated by an injectable `ExtractPrincipal(ctx) Principal` so the broker stays independent of `pkg/api/auth` (task 9 wires the real extractor). `LogAuditor` (slog-backed) ships as the production-acceptable fallback when no real audit store is configured — `MaskedPayload` is masked via task-1's `Secret.MaskForLog` so cleartext never reaches the log pipeline. New constants: `ActionGetSecret` / `ActionWriteSecret` / `ActionListSecrets` / `ActionDeleteSecret` / `ActionIssueDynamicSecret` / `ActionRenewLease` / `ActionRevokeLease` (Epic 12's audit query layer + the future `kscore-secrets audit` CLI grep these); `CacheBackendLabel = "cache"` so audit consumers distinguish cache-hit reads. Test fixture exercises 3-backend setup (`kv/` → file, `secret/` → vault, default = file) with the full happy-path + error matrix: routing dispatch (right backend called), default-backend fallback, no-route-no-default rejection, capability refusal (no dispatch, audit still fires), cache hit/miss/populate, Refresh bypasses cache, write/delete invalidate cache, dynamic secret records lease, RenewLease routes via directory, RevokeLease forgets + invalidates cache, lease-against-unknown-backend rejection (post-config-change scenario), audit count == op count across all methods, payload-masking on Write, principal propagation, Start fan-out + rollback on failure, double-Start rejected, double-Stop idempotent, Start-after-Stop rejected, Health pre-Start returns `ErrBackendNotStarted`. 96.9% coverage on `internal/secrets`; `-race` clean; project `make lint` + `make test` green.)_
4. **Encrypted-file backend** with AES-GCM encryption-at-rest + write-ahead approach for crash safety.
   _(landed: `internal/secrets/file` package — zero-deps trial-day-1 backend per §4.11. AES-256-GCM authenticated encryption + per-write `crypto/rand` nonce + atomic-rename writes (`<path>.tmp` → fsync → close → `os.Rename`; the rename IS the write-ahead — no separate WAL needed). On-disk envelope (41-byte fixed header): `[16]` magic `KSCORE-SECRETS\0\0`, `[1]` format version, `[8]` key fingerprint (`sha256(key)[:8]`), `[12]` nonce, `[4]` ciphertext length, `[N]` AES-GCM ciphertext+tag. Wrong-key boot surfaces a recognisable `errEnvelopeKeyMismatch` (vs opaque "decryption failed") so operator debugging is fast. Master-key resolver `ResolveMasterKey` supports v1.0 schemes `env:VAR` / `file:/path` / `inline:hex-or-base64`; hex (64 chars) tried first then base64 (std + URL, padded + raw); 32-byte binary keyfiles supported directly. Cloud KMS schemes (`gcp-kms:` / `aws-kms:` / `azure-kv:`) detected and rejected with a v2.0 pointer per FEATURES.md. `MasterKey.String()` emits `master-key(fp=<hex>)` — key bytes never leak through `%v`/`%s`. `Backend{Name "file" (overridable), Path, MasterKeySource}` declares `CapKV` + `CapList`; `IssueDynamicSecret` / `RenewLease` / `RevokeLease` all return `ErrInvalidBackend` wrapped with capability context (defense-in-depth against direct callers that bypass the broker's cap check). Start: cleans up any stale `.tmp` (crashed-write recovery), then either initializes an empty encrypted file (logs INFO with key fingerprint so operators see encryption errors at boot, not on first write) or decodes the existing one. CRUD: `GetSecret` returns a defensive clone; `WriteSecret` honours optional `CAS *uint64` (rejected mismatch wraps `ErrInvalidBackend`), monotonically bumps Version, preserves `CreatedAt` across updates, rolls back the in-memory mutation if disk persist fails (read-only-directory test covers the path); `ListSecrets` is metadata-only by contract with `Sort.Strings` + cursor-based pagination; `DeleteSecret` supports CAS too. Concurrency: a single `sync.RWMutex` guards the in-memory state; N=50 concurrent Get/Write goroutines clean under `-race`. State on disk is `fileState{Version, Secrets map[path]storedSecret}` JSON-encoded inside the encrypted envelope — schema version `1` for v1.0; future migrations bump it. Per-path history (KV v2 multi-version) intentionally out of scope: operators that need history use Vault (task 5). Broker integration test boots a real `secrets.Broker` against the file backend and round-trips Write → Get → Delete with audit events recorded on every op. New gate-v1.0 ROADMAP entry "Encrypted-file backend master-key rotation tooling" tracks the §4.11 dual-key-window gotcha; v0.1 procedure is operator-driven (stop → re-encrypt → start). 87.5% coverage on `internal/secrets/file`; project `make lint` + `make test` + `make docs-lint` + `-race` clean.)_

## Acceptance criteria

- [ ] Encrypted-file backend: write secret → read secret → delete secret round-trips with AES-GCM authenticated encryption.
- [ ] Vault backend (with `vault dev` server) — KV v2 read/write, dynamic DB credential issuance, lease renewal, lease revoke.
- [ ] Path-prefix routing: `kv/app/db` routes to file backend; `secret/data/foo` routes to Vault per config.
- [ ] Lease manager: dynamic secret issued → tracked → renewed at threshold → revoked on demand → removed from tracking.
- [ ] Transit ops: encrypt → decrypt round-trips; signed message verifies; batch encrypt 100 plaintexts in <1s with Vault.
- [ ] Cache hit-rate >80% on second access of same secret; cache invalidates on prefix-delete.
- [ ] All operations emit `secret.access` event in audit log with masked values.
- [ ] CLI: `kscore-secrets get path` returns cleartext (with audit log entry); `list` shows path + metadata only.
- [ ] Coverage >75% on `internal/secrets`; >80% on `pkg/secrets`.

## Risks

- **Cache invalidation on backend update** — explicit (refresh param or operator clear). Document.
- **Master-key rotation** breaks cache — mitigate with dual-key window.
- **Transit round-trips** add 50–200ms — batch ops materially help.
- **Lease renewal storms** — add jitter (default scheduler has it).
- **Audit log disk-full** — circuit-break + alert is mandatory.
- **Vault test dependency** — gate Vault tests behind `KSCORE_TEST_VAULT_ADDR`; CI runs `vault dev` in docker-compose.
